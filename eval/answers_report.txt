--- q06 C=3 G=5  how does password recovery by email work?
sources: login.py::recover_password, utils.py::generate_reset_password_email, login.py::recover_password_html_content, utils.py::generate_password_reset_token, login.py::reset_password
Password recovery is implemented as a three‑step flow:

1. **Request a recovery link** – `recover_password` receives the user’s e‑mail, looks up the user and (only if it exists) creates a JWT‑based reset token and sends an e‑mail.  
   * The endpoint is defined in `backend/app/api/routes/login.py:53‑74`【1†backend/app/api/routes/login.py:53-74】.  
   * The token is generated by `generate_password_reset_token(email)` (`backend/app/utils.py:105‑115`)【4†backend/app/utils.py:105-115】.  
   * The e‑mail content (subject and HTML body) is built by `generate_reset_password_email` (`backend/app/utils.py:70‑84`)【2†backend/app/utils.py:70-84】, which inserts the token into a link like `FRONTEND_HOST/reset‑password?token=…`.  
   * The e‑mail is finally sent with `send_email(...)` (lines 67‑71 of the same function).

2. **User clicks the link** – The front‑end opens the URL containing the token; the back‑end later validates it when the user submits a new password.

3. **Reset the password** – `reset_password` receives the token and the new password, verifies the token with `verify_password_reset_token`, fetches the user, and updates the password.  
   * This logic is in `backend/app/api/routes/login.py:77‑97`【5†backend/app/api/routes/login.py:77-97】.

Thus, the recovery works by generating a time‑limited JWT token, emailing a link that contains that token, and then validating the token when the user posts the new password.
